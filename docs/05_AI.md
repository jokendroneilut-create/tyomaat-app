# Työmaat.fi – AI / LLM

Miten ja missä kielimallia käytetään. Perusperiaate (ks. myös
[`01_ARCHITECTURE.md`](01_ARCHITECTURE.md)): **AI on valinnainen apuri, ei
pakollinen riippuvuus.** Deterministinen sääntö ensin, LLM vain kun se ei riitä.

## Malli ja rajapinta

- **Malli**: `claude-haiku-4-5` (Anthropic) — halpa ja nopea, riittää näihin
  poimintatehtäviin.
- **SDK**: `@anthropic-ai/sdk` (`client.messages.create`).
- **Rakenteinen ulostulo**: `output_config.format = { type: "json_schema", schema }`
  — malli palauttaa suoraan skeeman mukaista JSONia, ei jälkiparsintaa vapaasta
  tekstistä.
- **Prompt caching**: system-prompt merkitään `cache_control: { type: "ephemeral" }`,
  jolloin toistuvat kutsut samalla ohjeella ovat halvempia.

## Fail-open -periaate

Jokainen LLM-apuri tarkistaa `process.env.ANTHROPIC_API_KEY`:n ja **palauttaa
tyhjän tuloksen (null / [] ) ilman virhettä**, jos avainta ei ole tai kutsu
epäonnistuu. Näin putki toimii aina ilman AI:ta — LLM vain rikastaa, ei estä.

```
let cachedClient = null
function getClient() {
  if (!process.env.ANTHROPIC_API_KEY) return null
  if (!cachedClient) cachedClient = new Anthropic()
  return cachedClient
}
```

## Käyttökohteet

### 1. Relevanssiportti (harmaa alue)
`lib/agent/quality/scorers/llmRelevanceScorer.ts`

Kun deterministinen luokittelu jättää signaalin `unclassified`-tilaan (ei
selvästi relevantti eikä selvästi roska), LLM arvioi onko kyseessä oikea
rakennushanke. Päätös lokitetaan `llm_relevance_log`-tauluun ja sitä voi seurata
TIC:in AI-sivulta. Kytketty `saveSignal`-polkuun. Offline-eval olemassa laadun
mittaamiseen.

### 2. Työmaan osoitteen poiminta
`lib/agent/identity/extractWorksiteAddress.ts`

Hilman rakenteinen osoite on hankintayksikön (tilaajan) osoite; työmaan osoite
on usein vain vapaassa kuvaustekstissä. **Deterministinen regex ensin**
(postinumero + kunta, validoitu kuntarekisteristä); **LLM vain jos regex ei
löytänyt kaupunkia** — eli pienelle osalle, kustannus minimissä.

### 3. Kaavan konsulttien poiminta liiteotsikoista
`lib/agent/identity/extractConsultantsFromAttachments.ts`

Helsingin kaavaliitteiden otsikot ovat muotoa
"`<kaava>, <selvitystyyppi>, <Yritys> <pvm>`" (esim. "…kaupallinen selvitys,
Ramboll 26.8.2024"). LLM erottaa oikeat yritysnimet asiakirjatyypeistä (jotka
deterministinen jäsennin sekoittaa) ja päättelee kullekin roolin →
`metadata.consultants` (`{ name, role }`). Näytetään kortin "Selvitykset ja
konsultit" -osiossa.

### 4. Kohdetyypin luokittelu
`lib/agent/quality/resolveBuildingType.ts` →
`lib/agent/quality/scorers/llmBuildingTypeScorer.ts`

Kohdetyyppi on asiakkaan ensisijainen suodatin. **Sääntö voittaa**:
`inferBuildingType` lukee tyypin otsikosta, on mitattu lähes
virheettömäksi eikä maksa mitään. LLM:ää kysytään vain kun sääntö ei
osaa **tai kun säännön arvo on kanonisen sanaston ulkopuolella**
("koulu", "Julkinen rakennus", YVA:n oma luokitus) — sellainen arvo ei
osu asiakkaan suodattimeen lainkaan, joten hanke on käytännössä
tyypitön.

**Kaksi kutsua, joiden on oltava samaa mieltä.** Yksi kutsu antaa noin
10 % vääriä (mitattu 60 rivin otoksella 1.9.2026), eikä mallin oma
varmuusluku erottele niitä: molemmat otoksen selvät virheet olivat
0,95:n kaistalla. Erotteleva signaali on erimielisyys — sama otsikko sai
eri vastauksen eri kutsulla 9 rivillä 60:stä, ja kaikki löydetyt virheet
olivat siinä joukossa. Kutsut ajetaan rinnakkain, joten portti ei
hidasta tuontia. Lisäksi vaaditaan varmuus ≥ 0,8.

Kytketty `resolvePotentialProject`-polkuun eli ehdokkaan syntyhetkeen;
hyväksyntä kopioi `metadata.building_type` → `projects.property_type`.
Malli merkitsee jälkensä (`building_type_source: "llm"`), jotta arvaus
erottuu lähteen omasta tiedosta. Aikakatkaisu 15 s (D-155).

Vanha kanta korjataan `scripts/backfill-llm-building-type.ts`, joka
käsittelee sekä hankkeet että jonossa odottavat ehdokkaat.

## Mitä EI tehdä LLM:llä (tarkoituksella deterministinen)

- **Projektin luokittelu / negatiiviset hankkeet** (`projectClassifier`,
  `negativeProjects.ts`) — avainsana-/sanavartalopohjainen, ei LLM. Ennustettava
  ja ilmainen.
- **Kaavalähteiden jäsennys** (kuntakohtaiset collectorit/resolverit) —
  rakenteista dataa (WFS/REST/HTML), ei tarvita LLM:ää.
- **Vanhojen hankkeiden suodatus** — sääntöpohjainen (mennyt valmistumispäivä
  tekstistä, julkaisupäivä yli 24 kk).

## Kustannusnäkymä

Käyttö on pientä ja kohdennettua (Haiku, lyhyet promptit, prompt caching,
fail-open). Suurin osa putkesta on deterministinen; LLM osuu vain harmaan alueen
signaaleihin, osoitteen puuttuviin tapauksiin ja konsulttiotsikoihin. Uusien
hankkeiden LLM-kustannus on murto-osa sentistä per hanke.
